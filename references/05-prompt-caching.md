# 05 · 缓存友好与提示词排序

## 1. 缓存怎么命中

绝大多数 API 的前缀缓存规则：**从第一个 token 开始逐字匹配，遇到第一个不同就断。**

所以顺序决定命中率：

```
[系统提示][工具定义][技能/规范][项目约定][代码库索引]  ← 稳定，一次成型
[本轮问题][新日志][新 diff][临时数据]                  ← 变动，放最后
```

## 2. 五条规则

1. **稳定内容前置，且不要中途改。** 改一个字，后面全断。
2. **不要在会话中途插入新的系统级段落**（比如临时加一条规则），会截断缓存。要加就加在本轮消息里。
3. **同一项目连续作业。** 切换项目 = 换前缀 = 重新付全量。
4. **批量任务用同一套开场。** 10 个文件处理，用同一条 prompt 模板连发，只换末尾参数。
5. **长文档只读一次。** 读完立刻提炼成索引卡，后面引用索引卡而不是原文。

## 3. 提示词排序模板

```
# 固定层（永不变）
角色、输出格式约定、项目规范、目录结构索引

# 半固定层（一次任务内不变）
本次任务的目标与验收标准、约束

# 变动层（每轮变）
当前问题、最新报错、最新 diff、本轮数据
```

## 4. 反模式

| 反模式 | 代价 |
|---|---|
| 每轮重发一遍需求原文 | 每轮多付一遍 |
| 会话中途改系统提示 | 缓存全废 |
| 在开头堆 50K 的项目文档 | 每轮付费，且大部分用不上 |
| 同一会话里切三个项目 | 前缀反复失效 |
| 用「总结一下上面」代替落盘 | 总结本身也进历史，越滚越大 |

## 5. 成本对照

假设 20K 稳定前缀，命中缓存按 10% 计价：

| 场景 | 30 轮成本（相对） |
|---|---|
| 前缀稳定 | 20K×0.1×30 = 60K 等效 |
| 每轮改前缀 | 20K×1×30 = 600K 等效 |
| 差 10 倍 | — |

这就是为什么「别乱改开头」比「少说两句话」重要得多。

## 6. 落地清单

- [ ] 项目约定单独成文件（`AGENTS.md` / `CLAUDE.md`），每次会话只读一次
- [ ] 技能文本按需加载，不塞进系统提示
- [ ] 会话内不改固定层
- [ ] 批量任务同一模板
- [ ] 长文档读一次 → 生成索引卡 → 后续只用索引卡
