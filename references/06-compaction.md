# 06 · 压缩算法与保真度分级

## 1. 压缩的三档保真度

| 档 | 名称 | 做法 | 信息保留 | 适用 |
|---|---|---|---|---|
| F1 | 无损折叠 | 去重、折叠重复行、去掉空行/进度条 | 100% 关键信息 | 日志、构建输出 |
| F2 | 结构化提取 | 只保留字段/行号/命中片段 | 80~95% | JSON、表格、大文件 |
| F3 | 摘要重写 | 用自己的话重述要点 | 60~80%（有损） | 已完成阶段的对话历史 |

**规则：能 F1 就不 F2，能 F2 就不 F3。** F3 只用于「已经确认过的历史」，绝不用在待处理的原始数据上。

## 2. F1 无损折叠

```bash
# 去重计数
sort log | uniq -c | sort -rn

# 去空行与进度条
grep -vE '^\s*$|^\s*\[=*>?\s*\]|^\s*\d+%' build.log

# 折叠连续相同行
awk 'prev==$0{c++;next}{if(c)print "  ^ 重复 " c " 次"; print; c=0; prev=$0}'
```

## 3. F2 结构化提取

原则：**先定「我要做判断需要哪几个字段」，只取这几个。**

```bash
jq -r '.items[] | [.id, .status, .updated_at] | @tsv'
grep -oE '[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}' access.log | sort -u
awk -F'\t' '{print $1"\t"$3}'
```

## 4. F3 摘要重写（对话历史）

固定五段，顺序不能乱：

```
1. 目标：一句话
2. 已确认事实：3~7 条（带证据路径）
3. 已排除路径：2~5 条（防止重试）
4. 当前状态与卡点
5. 下一步：1~3 条
```

**禁止**在摘要里写「我们讨论了…」「然后我尝试了…」——过程不是信息。

## 5. 压缩时绝对不能删的东西

- 报错原文（第一次出现的完整版）
- 数字：端口、版本、ID、金额、时间
- 路径与文件名
- 用户的硬约束（「必须用 X」「不许碰 Y」）
- 已做出的决策及其理由
- 未决问题

## 6. 压缩标记规范

省略必须显式标注，否则下游会以为是全部：

```
…[省略 1,842 行，命中 12 处的完整内容见 /tmp/x.log]…
…[截断：原长 12,340 字符]…
…[重复 ×37：Connection reset by peer]…
```

## 7. 何时压缩

| 触发 | 动作 |
|---|---|
| 上下文 > 50% | 开始做结论落盘 |
| 上下文 > 60% | 强制压缩：写 HANDOVER + 丢弃原始输出 |
| 上下文 > 80% | 立即换会话（压缩本身已经很贵） |
| 阶段完成 | 无论百分比，都做一次 F1/F2 |

## 8. 压缩质量自检

压完问三句：
1. 只看这份压缩版，能不能独立复现结论？
2. 有没有哪个数字/路径丢了？
3. 有没有把「猜测」写成了「事实」？

三问有一个否 → 重新压。

## 9. 不要做的事

- 不要用「总之」「大概」「应该」这类词掩盖丢失的信息
- 不要把失败尝试全部删掉（那是最贵的知识）
- 不要压缩还没读懂的代码
- 不要用摘要替代 diff 复查
