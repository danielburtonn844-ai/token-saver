# 04 · 跨会话交接

## 1. 为什么必须写 HANDOVER

会话 A 干了 40 轮，上下文 80K。开新会话时：
- 把历史全带过去 → 80K 起步，后面每轮都在为它付费
- 读一份 300 token 的 HANDOVER → 成本降两个数量级，信息保留 90%

**结论：会话的产物不是聊天记录，是文件。**

## 2. 五段式结构（≤ 300 token）

```markdown
# HANDOVER: <项目名>

## 目标
一句话。

## 状态
已完成：…
进行中：…
卡点：…

## 关键决策
- 用 X 不用 Y，因为 …（防止下个会话推翻重来）

## 文件指针
- 源码：/path
- 配置：/path
- 日志：/path

## 下一步
1. …
2. …
```

要点：
- **决策 + 理由**比结论更重要。只写「用了 Redis」不够，要写「用 Redis 不用 PG，因为要 TTL 和原子计数」。
- **卡点要写清试过什么、为什么不行**，否则下个会话会重走一遍。
- **文件指针给绝对路径**，别给「那个脚本」。

## 3. 什么该写，什么不该写

| 该写 | 不该写 |
|---|---|
| 结论、决策、理由 | 完整命令历史 |
| 失败路径与原因 | 大段日志 |
| 文件路径 | 代码全文 |
| 未决问题 | 寒暄与过程 |
| 环境特殊坑（版本/权限） | 已经废弃的方案细节 |

## 4. 更新时机

- 每个阶段完成时（不是结束时才补）
- 上下文到 60% 时（强制）
- 要做破坏性操作前（留后路）
- 会话即将超时/切换前

## 5. 工具

```bash
python3 scripts/handover.py new  /path/to/HANDOVER.md
python3 scripts/handover.py check /path/to/HANDOVER.md   # 校验必填段/长度
python3 scripts/handover.py show  /path/to/HANDOVER.md   # 打印（≤300 token）
```

## 6. 新会话开场白模板

```
读 /path/HANDOVER.md 接手，不要读历史。
确认三件事：目标、当前卡点、下一步，然后直接干。
```

## 7. 多项目并存

`/var/minis/shared/<project>/HANDOVER.md`，一项目一份。
新会话先 `ls /var/minis/shared/*/HANDOVER.md` 找到对应项目，只读那一份。

## 8. 反模式

| 反模式 | 后果 |
|---|---|
| 「继续上次」但不给路径 | 新会话瞎猜，重做一遍 |
| HANDOVER 写 2000 行 | 比读历史还贵 |
| 只写结论不写理由 | 下个会话推翻重来 |
| 不写失败路径 | 同一个坑踩两次 |
