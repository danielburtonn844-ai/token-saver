# 03 · 子代理委派手册

## 1. 什么时候该外派

```
外派划算 ⟺ 脏输出 S × 剩余轮数 > brief B + 回流 R
```

实操判据（满足任一）：
- 预计工具输出 > 20KB
- 预计要跑 > 6 轮工具
- 要在 > 10 个文件里找线索
- 要爬 > 3 个页面/接口
- 机械性批量处理（格式转换、按清单核对、批量改名）
- 试错型调试（同一问题要试很多组合）

**不要外派**：1~2 条命令能查完；需要用户中途决策；强依赖当前对话的隐含语境；只剩 1~2 轮就收工。

## 2. brief 三要素

缺一个就会返工，返工比自己做还贵。

### 2.1 目标与验收

写「什么算完成」，不写「大概看看」。

❌ 「帮我看看这个项目有什么问题」
✅ 「找出 `src/` 下所有未捕获的 Promise rejection 风险点，每条给出文件:行号 + 触发条件 + 修复建议，按严重度排序，最多 10 条」

### 2.2 边界

- 可读路径 / URL 清单
- 允许写哪些文件（默认只读）
- 禁止事项（别装包、别改配置、别联网）
- 时间/预算上限

### 2.3 交付格式

- 只要结论，不要过程
- 字数上限（例如 ≤ 300 字）
- 必须附证据：`文件:行号` 或命令输出片段
- 未决问题最多 3 条

## 3. 模板

见 `templates/SUBAGENT_BRIEF.md`，直接抄。

## 4. 并行策略

独立子任务同时发，不要串行等结果：

```
任务 A：扫后端接口     ┐
任务 B：扫前端调用点   ├→ 并行 → 汇总冲突
任务 C：扫测试覆盖     ┘
```

**只在彼此不共享写目标时并行。** 两个子代理都改同一个文件 = 冲突 + 返工。

## 5. 回流协议

子代理回复必须压成这个形状：

```
结论：
- 3~5 条，每条一行

证据：
- src/api/auth.ts:42  —— 未捕获异常
- logs/err.log:118    —— 复现路径

未决：
- 需要确认 X 是否在生产环境启用
```

**禁止**把它的探索过程、命令历史、失败尝试搬回主上下文。要细节就让它写文件，主上下文只留路径。

## 6. 分级模型策略

| 活的性质 | 模型 | 理由 |
|---|---|---|
| 判断、设计、不可试错 | 主模型 | 错一次代价最大 |
| 常规实现、调试 | 主模型 | 需要上下文理解 |
| 机械转换、批量提取、格式核对 | 便宜模型 | 可验证，错了能一眼看出 |
| 大规模扫描、初筛 | 便宜模型 + 主模型复核 | 两段式 |

**降智红线：不可逆的操作、安全相关代码、金额计算，永远用主模型。**

## 7. 验收

子代理的产出不能直接信，至少做一项抽检：
- 随机抽 1~2 条证据，去文件里核对行号
- 让它给可执行的验证命令，你跑一遍
- 检查它有没有超范围（改了不该改的文件）

**省 token 不许省验收。**

## 8. 反模式

| 反模式 | 后果 |
|---|---|
| brief 写「帮我看看」 | 回来一堆废话，还得自己重做 |
| 让子代理回全部日志 | 等于没外派 |
| 串行发 5 个子任务 | 时间 5 倍，钱一样 |
| 子代理改同一批文件 | 冲突，合并成本爆炸 |
| 不看结果直接用 | 错误被放大 |
